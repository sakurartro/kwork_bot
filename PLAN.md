# План проекта: Kwork Parser Telegram Bot

Телеграм-бот, который парсит новые заказы с фриланс-биржи **Kwork** (https://kwork.ru/),
прогоняет их через нейросеть **Gemini** для оценки «можно ли выполнить работу полностью ИИ»,
и по одобренным заказам присылает готовый пакет для быстрого отклика.

---

## 1. Что должен уметь бот (функциональные требования)

### Команда `/start` — цикл парсинга и отбора заказов
1. Запускает цикл сбора новых объявлений с раздела заказов Kwork (`kwork.ru/projects`).
2. Каждое новое объявление (название + описание) отправляется в Gemini на **классификацию**:
   вопрос — «Может ли нейросеть выполнить эту работу полностью?».
   Если нет → Gemini возвращает `нет`, объявление отбрасывается.
3. Если Gemini одобрил, бот присылает пользователю **одним пакетом**:
   - 🔗 ссылку на объявление;
   - 📋 **копируемое** название работы (моноширинный блок);
   - 📋 **копируемое** описание работы;
   - 📋 **копируемое** сообщение заказчику — написанное «по-человечески»,
     так, чтобы **не было видно, что его писала нейросеть**.
4. Сразу после ТЗ Gemini генерирует **подробнейший промпт для Claude Code**
   по ТЗ заказчика — пользователь копирует его, вставляет в Claude Code и на выходе получает готовый файл/результат.
5. Между запросами к бирже — **рандомная задержка 90–150 секунд** (и другие защиты от блокировок).

### Команда `/chat` — человеческий ответ заказчику
- Пользователь вставляет в бота сообщение от клиента.
- Gemini генерирует **человечный, естественный ответ** (без «роботных» формулировок и следов ИИ).
- Бот присылает готовый текст для копирования.

## 2. Технологический стек

| Слой | Инструмент | Почему |
|------|-----------|--------|
| Язык | Python 3.11+ | асинхронность, богатая экосистема парсинга |
| Телеграм | `aiogram` 3.x | асинхронный, современный API, удобные роутеры |
| HTTP/парсинг | `httpx` + `selectolax`/`BeautifulSoup` | быстрый асинхронный клиент |
| JS-рендеринг (запасной путь) | `Playwright` (stealth) | если контент грузится через JS/защиту |
| ИИ | Google **Gemini API** (`google-generativeai`) | классификация + генерация |
| Хранилище | `SQLite` (через `aiosqlite`) | дедупликация просмотренных заказов |
| Конфиг | `pydantic-settings` + `.env` | секреты и настройки |
| Планировщик | `apscheduler` / внутренний цикл | периодический парсинг |
| Логи | `loguru` | удобное структурированное логирование |

> ⚠️ **Важно про доступ к Kwork.** У Kwork нет открытого публичного API для чтения ленты заказов.
> Парсинг ведётся по HTML/внутренним JSON-эндпоинтам и требует авторизованной сессии (cookies).
> Это накладывает риск блокировки — см. раздел 5. Обязательно соблюдать ToS биржи и не создавать
> избыточную нагрузку.

## 3. Архитектура и поток данных

```
Пользователь (Telegram)
        │  /start
        ▼
┌─────────────────┐      ┌──────────────────┐      ┌─────────────────┐
│   bot/handlers  │────▶ │  parser/kwork    │────▶ │ storage (dedup) │
└─────────────────┘      └──────────────────┘      └─────────────────┘
        │                        │  новые заказы
        │                        ▼
        │                ┌──────────────────┐
        │        ┌──────▶│  ai/gemini       │  1) классификация «да/нет»
        │        │       │                  │  2) сообщение заказчику
        │        │       │                  │  3) промпт для Claude Code
        │        │       └──────────────────┘
        │        │  задержка 90–150с (anti_block/delays)
        ▼        │
┌─────────────────┐
│ bot/formatting  │  → красивый пакет-сообщение в Telegram
└─────────────────┘

        │  /chat
        ▼
   ai/gemini (генерация человечного ответа) → пользователю
```

### Поток `/start` (пошагово)
1. `handlers.start` → запускает `parser.fetch_new_listings()`.
2. Парсер отдаёт список объявлений; `storage` отфильтровывает уже виденные (по `listing_id`).
3. Для каждого нового заказа:
   - `anti_block.delays.sleep_random(90, 150)` перед сетевым запросом;
   - `gemini.classify(title, description)` → `да` / `нет`;
   - если `да`:
     - `gemini.generate_client_message(...)` → человечное сообщение заказчику;
     - `gemini.generate_claude_prompt(...)` → детальный промпт для Claude Code;
     - `formatting.build_offer_message(...)` → собирает финальное сообщение;
     - отправка пользователю.
   - `storage.mark_seen(listing_id)`.

### Поток `/chat`
1. `handlers.chat` ловит вставленный текст клиента.
2. `gemini.generate_human_reply(client_message)` → ответ.
3. Отправка пользователю (копируемый блок).

## 4. Промпты для Gemini (логика, не код)

1. **Классификатор** — строгий системный промпт: «Оцени, может ли ИИ выполнить задачу
   ПОЛНОСТЬЮ без участия человека. Ответь только `да` или `нет`. Если требуется физический
   труд, доступы, живое общение, дизайн-вкус вне генерации и т.п. — `нет`.»
2. **Сообщение заказчику** — «Напиши короткий, живой, уверенный отклик от лица фрилансера.
   Без канцелярита, без признаков ИИ, без эмодзи-переспама. Тон — как у опытного исполнителя.»
3. **Промпт для Claude Code** — «На основе ТЗ заказчика составь максимально подробный
   технический промпт для Claude Code: контекст, требования, ограничения, ожидаемый формат
   результата (файл), критерии приёмки.»

Все шаблоны хранятся в `src/ai/prompts.py` — редактируются без изменения логики.

## 5. Защита от блокировок (anti-block)

- ⏱️ **Рандомная задержка 90–150 с** между запросами к бирже (`delays.py`).
- 🎭 **Ротация User-Agent** и реалистичных заголовков (`user_agents.py`).
- 🌐 **Поддержка прокси** (опционально, ротация пула) (`proxy.py`).
- 🍪 **Сессия/cookies** авторизованного аккаунта, аккуратное переиспользование (`session.py`).
- 📉 **Джиттер и лимиты**: не больше N запросов за окно времени, экспоненциальный backoff при 429/403.
- 🕒 Имитация «человеческого» ритма: нерегулярные интервалы, паузы, отсутствие ночной активности (опц.).
- 🔁 Аккуратная обработка ошибок: капча/бан → пауза и уведомление пользователя, а не долбёжка.

## 7. Конфигурация (`.env`)

| Переменная | Назначение |
|-----------|-----------|
| `TELEGRAM_BOT_TOKEN` | токен бота из @BotFather |
| `TELEGRAM_OWNER_ID` | ваш Telegram ID (бот работает только для вас) |
| `GEMINI_API_KEY` | ключ Google Gemini API |
| `GEMINI_MODEL` | напр. `gemini-2.5-flash` / `gemini-2.5-pro` |
| `KWORK_LOGIN` / `KWORK_PASSWORD` | учётка биржи (или готовые cookies) |
| `KWORK_COOKIES` | сохранённая сессия (альтернатива логину) |
| `PARSE_DELAY_MIN` / `PARSE_DELAY_MAX` | `90` / `150` |
| `PROXY_LIST` | список прокси (опц.) |
| `DB_PATH` | путь к SQLite |
| `LOG_LEVEL` | уровень логирования |

## 9. Риски и оговорки

- **ToS Kwork**: автоматический парсинг может нарушать правила биржи и вести к бану аккаунта.
  Использовать осознанно, на свой риск, с минимальной нагрузкой.
- **Хрупкость парсера**: вёрстка/эндпоинты Kwork меняются — потребуется поддержка селекторов.
- **Качество отбора Gemini**: возможны ложные «да» — финальное решение всегда за человеком.
- **«Незаметность ИИ»**: цель — естественный текст; гарантий полной неотличимости нет.
- **Приватность**: бот должен отвечать только владельцу (`TELEGRAM_OWNER_ID`).
